# Чек-лист AGENTS.md / CLAUDE.md

Источники — спецификация `agents.md` и документация Claude Code (память и
best practices):

- https://agents.md/
- https://code.claude.com/docs/en/memory
- https://code.claude.com/docs/en/best-practices

Пункт, где источники расходятся, помечен явно.

## 1. Файл вообще загружается

- [ ] **Claude Code читает `CLAUDE.md`, а не `AGENTS.md`.** Репозиторий с одним
      только `AGENTS.md` не получает инструкций в сессии. Лечится файлом
      `CLAUDE.md` с одной строкой `@AGENTS.md` (на Windows только так) или
      симлинком.
- [ ] Загрузку подтверждает `/context` — файл виден в списке memory files.
      Проверка глазами в файловой системе этого не доказывает.
- [ ] Точечная подгрузка правил по путям сделана механизмом **того харнеса,
      которым работает команда** — общего стандарта тут нет:

      | Харнес | Где лежит | Чем ограничивается |
      |---|---|---|
      | Claude Code | `.claude/rules/*.md` | `paths:` во фронтматтере; без него правило грузится всегда |
      | Cursor | `.cursor/rules/*.mdc` | `globs:` и `alwaysApply:`; у `.md` без фронтматтера ограничений нет |
      | Copilot | `.github/instructions/*.instructions.md` | `applyTo:`; на github.com работает не во всех поверхностях |
      | Codex и остальные по спеке | вложенные `AGENTS.md` | каталог, в котором лежит файл |

- [ ] Переносимый способ ограничить правило путями — **вложенный `AGENTS.md`**
      рядом с подпроектом: его читают все, у самого `AGENTS.md` фронтматтера
      нет и ограничить его нечем.
- [ ] Команда на нескольких харнесах: общее лежит в `AGENTS.md`, а специфика
      дублируется не текстом, а тонкими файлами-указателями на него.
- [ ] Процедуры и разовые сценарии вынесены в скиллы или их аналог: они
      грузятся по запросу, а не в каждой сессии.
- [ ] То, что обязано случаться всегда, оформлено хуком или git-хуком самого
      репозитория, который работает у всех независимо от харнеса. Файл
      инструкций — совет, а не принуждение.
- [ ] Личное отделено от командного: командное в репозитории, личное — в
      файле, который харнес читает только у владельца (`CLAUDE.local.md` под
      `.gitignore` в Claude Code).
- [ ] Про импорты `@path` в Claude Code: вложенность до четырёх переходов,
      импортируемое грузится при старте, то есть контекст не экономит.

## 2. Размер

- [ ] Файл до 200 строк (документация Claude Code). Исследование по AGENTS.md
      даёт ещё жёстче — после 150 строк отдача падает, а расход растёт.
- [ ] На каждую строку есть ответ: **какую ошибку агент сделает, если её
      убрать**. Нет ответа — строка уходит.
- [ ] Раздутый файл не «просто длинный»: правила из него начинают
      игнорироваться. Если агент упорно нарушает конкретное правило, первая
      гипотеза — файл длинный, а не правило непонятное.
- [ ] `IMPORTANT` и прочий нажим стоит максимум у одной-двух строк. Выделено
      всё — не выделено ничего.

## 3. Содержимое

Входит:

- [ ] команды, которые не угадать (точные флаги, свой пакетный менеджер);
- [ ] правила стиля, отличающиеся от дефолта языка;
- [ ] как гонять тесты и чем;
- [ ] этикет репозитория: имена веток, конвенции коммитов и MR;
- [ ] архитектурные решения, специфичные для проекта;
- [ ] причуды окружения: обязательные env, подъём стенда;
- [ ] грабли и неочевидное поведение.

Не входит:

- [ ] то, что агент выяснит чтением кода (структура каталогов, список
      зависимостей, обзор архитектуры);
- [ ] стандартные конвенции языка, которые модель знает и так;
- [ ] подробная документация API — вместо неё ссылка;
- [ ] часто меняющиеся данные;
- [ ] пересказ файла-за-файлом и длинные объяснения;
- [ ] самоочевидное вроде «писать чистый код».

## 4. Формулировки

- [ ] Инструкция проверяема: «отступ два пробела», а не «форматируй красиво»;
      «запусти `pnpm test` перед коммитом», а не «тестируй».
- [ ] Один пример кода вместо трёх абзацев описания.
- [ ] Нет противоречий между файлом, вложенными файлами и правилами: при
      конфликте модель выбирает произвольно.
- [ ] Целевое поведение сформулировано положительно. Запрет тащит запрещённое
      в контекст и делает его доступнее.
- [ ] **Исключение, где источники расходятся:** документация Claude Code
      настаивает, что без явного «не делай так» модель возьмёт самый частый
      паттерн, который может быть чужим. Разрешение — называть и цель, и
      конкретный неверный дефолт: «переходы через `navigateToLocale()`;
      `router.push()` в коде встречается и это legacy».
- [ ] Заголовки и списки вместо плотных абзацев.
- [ ] Одно понятие — одно слово. Слово, значащее две вещи, разводится или
      фиксируется в словаре домена.

## 5. Проверяемость работы

- [ ] Из файла понятно, чем агент проверит себя: тесты, сборка, линт,
      скриншот. Без этого «выглядит готовым» остаётся единственным сигналом.
- [ ] Сказано, что делает CI на самом деле, и что он **не** ловит.
- [ ] Критерий приёмки сформулирован как состояние, которое видно: сьют
      зелёный, линт чист.

## 6. Свежесть

- [ ] Каждое число в файле — это копия результата команды (размер сьюта,
      время прогона, количество ошибок типов, сколько в коде legacy-вызовов).
      Оно протухает молча, и агент потом ищет поломку там, где её нет, или
      списывает чужую красноту на себя. Поэтому: рядом с числом дата и команда,
      которой оно снято, а при проверке число снимается заново, а не
      переписывается из прошлой версии.
- [ ] Число, которое дёшево получить и которое ничего не решает, не хранится
      вовсе: «переходы через `navigateToLocale()`» работает, а «74 против 6
      вызовов» только устаревает.
- [ ] Указатели ведут в существующие файлы, команды из файла запускаются.
- [ ] Факты сверены с кодом: имя константы, путь, флаг — проверены грепом, а
      не памятью.
- [ ] Мёртвые правила удалены. Правило, которое некому прочитать (живёт в
      файле, который в этой ветке не грузится), не работает вовсе.

## 7. Переносимость

- [ ] В монорепозитории вложенный файл лежит рядом с подпроектом: ближайший к
      правке побеждает.
- [ ] Прямые указания пользователя в чате бьют любой файл — файл не место для
      попыток это запретить.
- [ ] Стековое (команды, замеры, конвенции, пути) не копируется из чужого
      проекта: чужие числа хуже пустоты.
