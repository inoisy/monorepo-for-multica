# Разведка Nuxt

Читать только после выбора ветки Nuxt по SKILL.md, включая `ssr: false`;
для Vue без Nuxt использовать VUE.md. При узком запросе — только затронутые
пункты. Проверки SSR, Nitro и других возможностей выполнять при их наличии. Версии, режим приложения, модули и
соглашения устанавливаются по этому репозиторию, без переноса из соседнего.
Команды проверять по VERIFY.md. Пункт без источника остаётся непроверенным.

Это вопросы к коду, а не готовая глава AGENTS.md. В итоговые инструкции
попадают только сведения, влияющие на действия агента и неочевидные из
одного конфига. Найденное расхождение с кодом может быть legacy: канонический
способ определяется действующими правилами или решением команды.

| Область | Что установить | Что стоит записать при наличии |
|---|---|---|
| Структура и запуск | Версия Nuxt, `srcDir`, layers, modules, SSR/SPA/prerender, scripts и обязательные env | Неочевидный корень исходников, способ запуска нужного сайта или окружения; генерируемые каталоги, в которых не надо искать исходники |
| Автоимпорты | Настройки imports/components, общие composables, отличия приложения и тестового раннера | Где использовать автоимпорты, а где явные импорты; как подключать типы и моки в тестах |
| SSR и гидратация | Где выполняется код, клиентские плагины и компоненты, доступ к браузерным API, источники недетерминированной разметки | Подтверждённые ловушки гидратации и принятый способ изолировать браузерный код; не вводить отключение SSR как общий обход |
| Данные и Nitro | Использование `useFetch`, `useAsyncData`, `$fetch`, проектных обёрток, server/api; ключи, watch, headers, cookies и runtimeConfig | Канонический способ запроса; случаи устаревшего кэша и повторных запросов; передача контекста пользователя и граница серверной конфигурации |
| Роутинг | Pages, router options, middleware, layouts, page meta, locale-aware хелперы | Где задаётся метаинформация и каким хелпером переходить; почему соседний код может быть legacy |
| Состояние | `useState`, Pinia и другие принятые хранилища, persist, cookies, инициализация на сервере и клиенте | Как сохраняется и сбрасывается состояние; обнаруженные риски смешения запросов, пользователей и страниц |
| Компоненты и формы | UI-библиотека, модалки, поля, валидация, согласия, капча, аналитика | Ссылки на канонические компоненты и условия чтения инструкций для формы; API библиотек целиком не копировать |
| i18n | Используемый модуль или собственный механизм, источники ключей и локализованные маршруты | Как добавлять пользовательский текст; подтверждённые исключения для отдельных разделов |
| Стили и адаптив | SCSS/CSS, scoped, токены, миксины, источник брейкпоинтов | Канонические токены и миксины; неочевидное определение мобильной версии; не копировать числовые значения из другого проекта |
| Проверки | Vitest или другой раннер, Nuxt test utils, окружение DOM, браузерные тесты, eslint/stylelint/vue-tsc | Рабочие команды, окружение и моки; критерий проверки типов при известном общем долге; реальные обязанности CI |
| Проверка глазами | Dev-сервер, страницы для разработки, фикстуры, выбор сайта/филиала, доступный браузерный инструмент | Воспроизводимый URL и необходимые env; сценарии для мобильной/десктопной версии, если это принято в проекте |

Для каждой найденной ловушки записать источник, условие проявления и действие
агента. Например, если проект использует собственную навигацию с локалью,
назвать найденный хелпер и область его применения. `navigateToLocale()`,
запрет `definePageMeta`, свои `$`-хелперы и конкретные SCSS-миксины не считать
встроенным стандартом Nuxt.

Общие для всех задач сведения оставить в корне. Правила только для `.vue`,
тестов или `server/` ограничить путями механизмом харнеса. Разбор конкретной
проблемы — «данные не обновились», «гидратация расходится», «тест не видит
автоимпорт» — вынести в обычный документ с условным указателем по SKILL.md.
Пустые документы под все строки таблицы не создавать.

Готово, когда у выбранных областей есть источник и статус, а в итоговый файл
попали подтверждённые правила проекта вместо справочника по Vue/Nuxt.
