# Стандарт Vue/Nuxt-проектов Лоции

Скилл предназначен для сотрудников Лоции: этот стандарт применяется по
умолчанию, без вопросов о языке, трекере и формате коммитов. Это единый
источник общих соглашений для сборки AGENTS.md; в итоговый файл переносится
их текст, а не ссылка на локально установленный скилл.

Явные исключения проекта и указания пользователя приоритетнее. При конфликте
показать конкретное расхождение; независимую работу продолжить. Для явно
указанного внешнего проекта стандарт не применять.

## Общие соглашения

- отвечать по-русски; сообщения коммитов, описания и комментарии MR,
  комментарии в коде и тестах также писать по-русски;
- ветка на задачу `t-<номер>-<слаг>`, заводится от базовой ветки проекта;
- для работы без задачи — служебный номер `12345`: ветка
  `t-12345-<слаг>`, коммит с `T-12345`;
- заголовок коммита — `type(scope): описание. T-<номер>`, и это не вкусовщина:
  для проектов с серверным `cmd-linter` на GitLab `git01` используется
  следующий формат (наличие проверки сверить с проектом):

  - `type` — один из `feat`, `fix`, `chore`, `docs`, `test`, `refactor`, `ci`,
    `build`, `perf`, `style`;
  - `scope` в скобках необязателен, но если есть — от двух символов; `!` перед
    двоеточием для breaking change допускается;
  - описание — минимум пять символов, заголовок целиком — минимум тридцать;
  - в конце через пробел `T-<номер задачи>`, без него коммит не уйдёт.

  Если в проекте есть `commitlint.config.*` — прочитать его и сослаться
  на него вместо копирования списка. Совпадение с серверным правилом
  проверить отдельно; расхождение указать как конфликт;
- первой строкой описания MR — ссылка на задачу в Сфере
  `https://sphere.loodsen.ru/company/personal/user/<id>/tasks/task/view/<номер>/`;
- таргет MR задаётся явно, иначе GitLab подставит дефолтную ветку;
- постановка и комментарии берутся из Сферы через `mcp__sphere__get_task`
  по номеру задачи; из URL сохраняются номер задачи и id пользователя для
  ссылки в MR. Если инструмент недоступен, указать ограничение и запросить
  текст постановки, не подменять источник задачи другим трекером;
- в результате работы нет следов инструмента: ни `Co-Authored-By` с именем
  нейросети, ни «Generated with», ни ссылок на сессию — ни в коммитах, ни в
  MR, ни в задачах, ни в коде.

## Что выяснять в каждом проекте

Общие соглашения выше не требуют повторного согласования. Разведкой установить:

- базовую ветку и таргет MR: `stage` не назначается всем проектам автоматически;
- пакетный менеджер и команды из scripts, lock-файла и конфигов;
- вариант Vue без Nuxt или Nuxt, версии и режим приложения — по развилке
  в [SKILL.md](./SKILL.md); затем читать только соответствующий справочник;
- команды unit/component/e2e-тестов, линта, проверки типов и роль CI;
- способ запуска фронтенда, env, адреса стендов и средства проверки в браузере;
- особенности адаптива, переводов, роутинга, запросов и UI-компонентов,
  если они влияют на работу в этом проекте.

Конкретные команды `pnpm`, Nuxt-автоимпорты, брейкпоинты и правила навигации
из одного проекта не становятся стандартом остальных. Обязательность TDD,
полного сьюта и проверок перед push брать из действующих правил проекта;
новые общие требования к разработке вводит команда, а не скилл.
