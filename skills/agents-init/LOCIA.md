# Профиль Лоции

Применять только для подтверждённого проекта Лоции. Это заготовки:
явные правила проекта и ответы пользователя приоритетнее. Показывать для
уточнения только расхождения и отсутствующие договорённости.

- отвечать, коммитить и писать в MR по-русски;
- ветка на задачу `t-<номер>-<слаг>`, заводится от базовой ветки проекта;
- для работы без задачи — служебный номер `12345`, если команда использует
  это соглашение: ветка `t-12345-<слаг>`, коммит с `T-12345`;
- заголовок коммита — `type(scope): описание. T-<номер>`, и это не вкусовщина:
  для проектов с серверным `cmd-linter` на GitLab `git01` используется
  следующий формат (наличие проверки сверить с проектом):

  - `type` — один из `feat`, `fix`, `chore`, `docs`, `test`, `refactor`, `ci`,
    `build`, `perf`, `style`;
  - `scope` в скобках необязателен, но если есть — от двух символов; `!` перед
    двоеточием для breaking change допускается;
  - описание — минимум пять символов, заголовок целиком — минимум тридцать;
  - в конце через пробел `T-<номер задачи>`, без него коммит не уйдёт.

  Если в проекте есть `commitlint.config.*` — прочитать его и сослаться
  на него вместо копирования списка. Совпадение с серверным правилом
  проверить отдельно; расхождение указать как конфликт;
- первой строкой описания MR — ссылка на задачу в Сфере
  `https://sphere.loodsen.ru/company/personal/user/<id>/tasks/task/view/<номер>/`;
- таргет MR задаётся явно, иначе GitLab подставит дефолтную ветку;
- постановка берётся из Сферы через MCP, а не пересказом от человека;
- в результате работы нет следов инструмента: ни `Co-Authored-By` с именем
  нейросети, ни «Generated with», ни ссылок на сессию — ни в коммитах, ни в
  MR, ни в задачах, ни в коде.

Что из этого спорно в конкретной команде — решает пользователь, а не скилл.
