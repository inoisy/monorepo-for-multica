# Разведка Vue без Nuxt

Читать после выбора ветки Vue без Nuxt по SKILL.md. Для Nuxt, включая
SPA-режим, использовать NUXT.md. При узком запросе исследовать только
затронутые области; команды и источники проверять по VERIFY.md.

Определить, это приложение или библиотека компонентов. Для библиотеки
проверять сборку, exports и среду демонстрации; наличие роутера, состояния
приложения и серверной части не предполагать.

| Область | Что установить | Что записать при наличии |
|---|---|---|
| Запуск и сборка | Версия Vue, Vite/Vue CLI/другой сборщик, точка входа, scripts, конфиги env и proxy | Неочевидные условия запуска и выбор окружения; границы исходников и генерируемых файлов |
| Компоненты | Composition/Options API, `script setup`, соглашения props/emits, регистрация компонентов | Канонический стиль проекта и подтверждённые исключения; смешение стилей не объявлять миграцией без основания |
| Импорты | Алиасы, плагины автоимпорта, глобальные компоненты, сгенерированные декларации | Где нужны явные импорты и как тесты получают те же зависимости; автоимпорты Nuxt не предполагать |
| Роутинг | Vue Router или другой механизм, таблица маршрутов, guards, lazy loading, история и base URL | Принятый способ навигации, авторизации и настройки маршрутов; файловый роутинг включать только при наличии соответствующего инструмента |
| Данные | Fetch/Axios/другой клиент, обёртки API, авторизация, отмена запросов, обработка ошибок | Канонический клиент и неочевидные правила обновления данных; Nuxt composables не назначать без реализации |
| Состояние | Pinia/Vuex/другое решение, composables, persist и сброс | Где хранится состояние и как сбрасывается при смене пользователя или страницы |
| UI и формы | Библиотека компонентов, модалки, валидация, капча, согласия и аналитика | Канонические компоненты и указатели на инструкции для конкретных сценариев |
| i18n и стили | Источники переводов, locale-aware навигация, CSS/SCSS, токены, миксины и брейкпоинты | Способ добавления текста, адаптива и стилей; исключения проекта |
| Проверки | Unit/component/e2e-раннеры, Vue Test Utils при наличии, DOM-окружение, линт и типы | Проверенные команды и моки роутера, store и API; обязанности CI и критерий приёмки |
| Проверка глазами | Dev-сервер, Storybook/стенды при наличии, env и браузерный инструмент | Воспроизводимые URL и сценарии проверки интерфейса |

Vue без Nuxt не означает обязательную SPA: если найдена собственная SSR-
интеграция, исследовать её точки входа, гидратацию и изоляцию состояния по
запросам. Инструкции брать из её реализации, не подставлять Nitro, Nuxt
plugins, `useAsyncData` и `runtimeConfig`.

Для каждой ловушки записать источник, условие и действие агента. В итоговый
AGENTS.md переносить только неочевидные правила проекта, а подробности
выносить по механике SKILL.md. Пустые разделы и обзор Vue не создавать.

Готово, когда выбранные области имеют источник и статус, а правила Nuxt
не попали в проект без подтверждённого механизма, к которому они относятся.
