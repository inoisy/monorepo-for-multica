# Проверка существующего AGENTS.md

Порядок важен: файл, который не грузится, бессмысленно вычитывать по
формулировкам. Сначала определить область запроса, прочитать действующие
инструкции по пути к ней и снять `git status`. Проверять только выбранную
область; родительские инструкции учитывать, соседние подпроекты не менять.
Глубину и бюджет проверки выбрать по VERIFY.md: узкий запрос не превращать
в полный аудит; для пунктов вне области это явно указать в отчёте.

## 1. Загружается ли он

Для Claude Code — есть ли `CLAUDE.md` или импорт `@AGENTS.md`. Для правил —
ограничены ли они по путям механизмом своего харнеса (`paths:`, `globs:`,
`applyTo:`) и не написаны ли они в формате, которого команда не читает.

Проверить корень и подпроекты отдельно для каждого используемого харнеса.
В Claude Code вложенному `AGENTS.md` нужен соседний `CLAUDE.md` с импортом:
импорт в корне его не подключает. Существующие инструкции сохраняются.

Наличие файла на диске загрузку не доказывает. В Claude Code проверить
`/context` в новой сессии и после чтения файла подпроекта. Для другого
харнеса использовать его диагностику. Недоступную сессию отметить
непроверенной и описать владельцу способ проверки.

Готово, когда для корня и подпроектов указан результат проверки загрузки
в каждом используемом харнесе; недоступные проверки перечислены отдельно.

## 2. Обмер

Строки, дубли, противоречия. Двести строк — ориентир для пересмотра объёма,
а не доказательство ошибки. Для сокращения назвать лишние или переносимые
фрагменты. Совпадающие по смыслу куски в основном файле и правилах
проверить на расхождения.

Готово, когда длина названа числом, а каждый дубль — парой мест.

## 3. Проверка фактов

Применить [VERIFY.md](./VERIFY.md): проверить команды с учётом их эффектов,
пути и имена — по репозиторию, указатели — на существование цели. У чисел
проверить источник и влияние на решение; доступные замеры обновить.
Договорённости команды не требуют подтверждения кодом и сохраняются до
явной отмены. Сокращение соглашений и различия вложенных правил оценивать
по VERIFY.md; неразрешённые конфликты показать с источниками.

Готово, когда у каждого факта есть источник и статус. Опровергнутое отделено
от непроверенного; недоступное окружение не означает, что инструкция ложна.

## 4. Чек-лист

[CHECKLIST.md](./CHECKLIST.md) по пунктам: на каждое нарушение — строка файла
и то, какое поведение агента оно портит.

Готово, когда у каждого пункта чек-листа есть вердикт. Пункт, до которого не
дошли руки, отмечается непроверенным, а не молча пропускается.

## 5. Отчёт

По убыванию вреда: не грузится → врёт → противоречит себе → раздуто →
сформулировано слабо. Отдельно перечислить непроверенное и причины.
В режиме аудита предложить правки; если пользователь уже попросил исправить,
внести подтверждённые исправления. Спорные договорённости сохранить до
решения владельца.
