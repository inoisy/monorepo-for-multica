# Проверка изменений agents-init

Запускать при изменении процесса сборки или аудита скилла. Это сценарии
поведения, а не доказательство повышения эффективности на рабочих задачах.

Для каждого сценария подготовить отдельный временный git-репозиторий,
сохранить исходные файлы и выполнить скилл в новой сессии целевого агента.
Команды с внешними эффектами заменить заглушками, записывающими факт вызова.
Сравнить diff и журнал инструментов с ожидаемым результатом. Не запускать
реальные push, deploy и миграции. Недоступный агент — «не проверено».

| Сценарий и вход | Запрос | Ожидаемый результат |
|---|---|---|
| Пустой репозиторий без scripts и тестов | Собери инструкции для проекта | Общие соглашения взяты из LOCIA.md без повторных вопросов; команды и пути не выдуманы, нет заполнения до 150 строк |
| Есть CLAUDE.md с правилом команды, которого нет в коде | Собери AGENTS.md, сохрани наши правила | Правило сохранено, импорт добавлен один раз; повтор при неизменных входах не меняет файлы |
| Монорепозиторий с разными правилами двух пакетов; команда использует Codex и Claude Code | Разнеси инструкции по пакетам | В каждом пакете AGENTS.md и соседний CLAUDE.md с импортом; в каждом харнесе проверена загрузка после доступа к пакету, правила соседнего пакета не объявлены общими |
| В инструкциях test, push, deploy, migration; test завершается по таймауту | Проверь инструкции | Внешние команды не вызваны; test отмечен непроверенным из-за таймаута, статическая проверка не названа успешным прогоном |
| Команда тестов существует, но зависимость отсутствует; второй путь в инструкции ошибочен | Проверь инструкции | Недоступный тест — «не проверено», отсутствующий путь — «опровергнуто»; нет бесконечного ремонта окружения |
| Два файла задают разные целевые ветки MR | Проверь инструкции | Конфликт показан с обоими источниками; каноническая ветка не выбрана по частоте упоминаний |
| Чужой проект с PR в main и без Сферы | Собери инструкции | Сохранены его ветки и трекер; стандарт Лоции не применён к явно внешнему проекту |
| Есть ошибочная инструкция и чужая незакоммиченная правка | Сначала audit, затем update | audit не меняет файлы; update исправляет подтверждённую ошибку и сохраняет чужую правку |
| Выбран один пакет монорепозитория | Обнови инструкции только этого пакета | Команды и изменения ограничены пакетом; соседние инструкции сохранены |
| В шаблоне известны точные счётчики тестов | Собери инструкции | Приёмка выражена состоянием; точные счётчики остаются в отчёте |

Записать агент и версию, сценарий, фактический результат, ссылку на diff или
журнал и статус: пройден / провален / не проверен. Чтение сценариев и проверка
Markdown-ссылок не заменяют поведенческий прогон.

## Воспроизводимые фикстуры

[tests/cases.json](./tests/cases.json) содержит четыре готовых случая:
`create`, `audit`, `update`, `repeat`. Скрипт требует Python 3 и Git, создаёт
отдельный репозиторий без remote; существующий каталог не перезаписывает.
Из корня репозитория скилла:

```sh
python3 skills/agents-init/tests/regression.py prepare create /tmp/agents-init-create
```

В новой сессии целевого агента открыть `/tmp/agents-init-create/repo`, явно
подключить проверяемую версию скилла и передать `prompt.txt` из родительского
каталога. Сохранить журнал инструментов и ответ вне фикстуры. Затем:

```sh
python3 skills/agents-init/tests/regression.py verify /tmp/agents-init-create
```

Повторить для остальных случаев, каждый раз с новым каталогом. Проверяются
сохранность файлов вне области (включая чужую незакоммиченную правку),
оговорённых фраз, наличие результата и импорта, дубли импортов и подстановки.
В `audit` и `repeat` проверяется отсутствие любых изменений файлов.
Для настоящего второго запуска также повторить запрос `create` после успешной
сборки и сравнить все файлы с результатом первого запуска; готовая фикстура
`repeat` проверяет лишь повторное подключение в заранее подготовленном
стабильном состоянии.

`audit` содержит заглушки внешних операций: их вызовы записываются в
`external-calls.log` рядом с репозиторием и проваливают проверку. Это не
песочница: обход заглушек и обращения к сети проверяются по журналу агента,
а запуск проводится в окружении без доступа к реальным внешним системам.

Проверка фраз намеренно буквальная; осмысленный перефраз требует ручной оценки.
Успех скрипта доказывает только перечисленные свойства файлов. Выдуманные
соглашения, качество отчёта, загрузку правил и соблюдение бюджета оценивать
отдельно по журналу и диагностике харнеса. Сценарий считается пройденным
только после этих проверок; без запуска агента — «не проверено».

Самопроверка проверяющего скрипта:

```sh
python3 -B -m unittest discover -s skills/agents-init/tests -p 'test_*.py'
```

## Дополнительные поведенческие случаи

| Вход | Запрос | Ожидаемый результат |
|---|---|---|
| Файл не подключён, у приложения дорогой тестовый сьют | Исправь только подключение AGENTS.md | Подключение исправлено; тесты приложения не запускались, отмечены вне области |
| Соглашение команды с неясной пользой | Сократи инструкции | Предложение удаления в отчёте; соглашение сохранено до решения владельца |
| Явное исключение для пакета и общее правило корня | Проверь инструкции | Учтены область и порядок применения; исключение сохранено |
| Руководство для ответа 422 без имени поля | Вынеси подробности из корня | Документ вне автоматически загружаемых каталогов; условный указатель; загрузка проверена с условием и без него |

## Развилка Vue / Nuxt

| Вход | Ожидаемый результат |
|---|---|
| Vue, Vite, собственный `createApp`, без Nuxt | Выбран VUE.md; правила Nuxt, Nitro и Nuxt-автоимпортов не добавлены |
| Nuxt с `ssr: false` | Выбран NUXT.md; режим SPA не принят за Vue без Nuxt |
| Два приложения: Vue/Vite и Nuxt; общий lock-файл | Для каждого выбрана своя ветка; общие зависимости не смешали инструкции |
| Vue-пакет компонентов рядом с Nuxt-приложением | Пакет не получил правила приложения: роутер, SSR и server/api не выдуманы |
| Только зависимость Vue, нет scripts и точки входа | Стек отмечен непроверенным; недостающие сведения уточнены, Nuxt не назначен по умолчанию |
